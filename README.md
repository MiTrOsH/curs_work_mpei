# Распознавание и синонимическое обезличивание ПДн

Программа ищет фамилию, имя, ИНН, номер паспорта, номер банковской карты, ОГРНИП, IP-адрес, E-mail, номер свидетельства о рождении и код КЛАДР. Веса дообученного распознавателя находятся в папке **model**. Для демонстрации не нужны обучение, GPU или загрузка модели из сети. Сеть нужна для первой установки библиотек и отдельно для загрузки исходного энкодера при повторном расчёте BERTScore.

Метки имён и фамилий проходят дополнительную проверку словарной морфологии и синтаксиса предложения. В примерах «Юра Волков любит волков» и «Юра волков любит Волков» распознаются первое имя и фамилия рядом с ним. Глагол «любит» сохраняется, а последнее слово трактуется как дополнение во множественном числе. В сочетаниях «Волков любит Юру» и «Юра любит Волковых» фамилии сохраняют свою роль в распознавании. Контекстная проверка выполняется на CPU с помощью Natasha.

### Запуск в Windows

Распакуйте архив и откройте PowerShell в папке, где лежит main.py. Команды рассчитаны на Python 3.12.

    py -3.12 -m venv .venv
    .\.venv\Scripts\python.exe -m pip install torch==2.6.0 --index-url https://download.pytorch.org/whl/cpu
    .\.venv\Scripts\python.exe -m pip install -r requirements.txt
    .\.venv\Scripts\python.exe main.py interactive --device cpu

Пункт **1** показывает типы и границы найденных атрибутов, пункт **2** — текст после замен и новые границы. Вводится одна строка. **0** завершает программу. Если PyTorch с CUDA уже установлен в имеющемся окружении, используйте его Python и при желании укажите --device cuda; ставить другой PyTorch для этого не требуется.

Для демонстрации сразу всех классов:

    .\.venv\Scripts\python.exe main.py detect --file examples/demo.txt --bio --device cpu
    .\.venv\Scripts\python.exe main.py anon --file examples/demo.txt --device cpu --seed 19 --strict

Без --seed каждый обычный запуск выбирает новые случайные замены; заданное число фиксирует результат для демонстрации. Добавьте --json для вывода данных в формате JSON. В режиме --strict ошибка построения допустимой замены прерывает обработку. В обычном режиме на месте проблемной сущности появляется маска, а программа выдаёт предупреждение. Ввод файла поддерживает многострочный UTF-8.

Короткий текст для интерактивной защиты:

> Женя Иванова подписала согласие. Документы передали Жене Ивановой. Иван Иванов-Петров передал документ. От Ивана Иванова-Петрова поступил ответ. ИНН: 500100732259; повтор: 5001 00732259.

Эта команда проверяет обработку имён разного рода в одном предложении.

    .\.venv\Scripts\python.exe main.py anon --text "Женя Иванов передал Жене Ивановой что-то" --device cpu --seed 19 --strict

После «передал» получатель «Жене Ивановой» стоит в дательном падеже. В этом контексте обе формы имени распознаются как NAME. В результате первое имя имеет мужской род, второе — женский и дательный падеж.

### Метрики распознавания в PowerShell

После установки зависимостей выполните команду из папки проекта, в которой лежит evaluate.py.

    .\.venv\Scripts\python.exe evaluate.py --data data/test.jsonl --model model --device cpu --output results_local

В консоли появятся Precision, Recall и F1 по каждому из десяти атрибутов. «Поддержка» означает число эталонных токенов класса. Под таблицей выводятся macro-F1 и weighted-F1 по типам токенов, по строгим BIO-меткам и по точному совпадению типа и границ. С порогами задания сравнивается строка «BIO без O». Macro-F1 даёт классам одинаковый вес, а weighted-F1 учитывает число токенов каждого класса.

В **results_local/recognition.json** блок **typed.per_attribute** содержит метрики и числа TP, FP, FN для отдельных атрибутов, **typed.aggregate** — средние по типам, **bio.aggregate** — средние по BIO-меткам без O. **results_local/predictions.jsonl** содержит распознанные интервалы по каждому документу.

### BERTScore и автоматические тесты

    .\.venv\Scripts\python.exe -m pip install -r requirements-eval.txt
    .\.venv\Scripts\python.exe benchmark_semantics.py --results results_local --device cpu
    .\.venv\Scripts\python.exe -m pytest -q

benchmark_semantics.py использует результаты этого распознавания на том же наборе и версию исходного RuBERT-tiny2, зафиксированную в коде. При первом вычислении скачивается около 118 МБ весов. Если исходная модель есть локально, передайте --encoder ПУТЬ; папка model из архива содержит дообученный NER и не является энкодером для этого эксперимента. Готовые численные результаты включены, повторный расчёт для демонстрации не обязателен.

Файлы **data/train.jsonl**, **data/validation.jsonl** и **data/test.jsonl** включены. Для их восстановления из исходного архива служит prepare_data.py. Для повторного обучения с исходного RuBERT-tiny2: **python train_model.py --device cpu --output model_retrained**. Скрипт скачивает исходную модель; дополнительно можно указать --base ПУТЬ. Для оценки новой модели используйте evaluate.py --model model_retrained --output results_retrained, а затем benchmark_semantics.py --results results_retrained. Сдаваемый набор весов при этом не изменяется.

Проверка реквизитов формальная: программа не обращается в реестры, банки, DNS или почтовые системы. Синтетические примеры служат для проверки алгоритма. При обработке других форматов возможны пропуски; например, слитный паспорт и цифровой КЛАДР требуют подписи в тексте. Оценки относятся к приложенной тестовой выборке.
